# LEASE Memory Context

面向 SillyTavern 的轻量记忆表格、表格总结与独立向量检索插件。

> 本项目基于 [gaigai315/ST-Memory-Context](https://github.com/gaigai315/ST-Memory-Context) 修改，保留原项目贡献者的署名，并按照原项目 README 声明的 MIT License 发布。本仓库是由 LEASE 维护的非官方衍生版本，与原作者不存在官方隶属或背书关系。详细归属与改动范围见 [ATTRIBUTION.md](ATTRIBUTION.md)。

## 保留功能

- 记忆表格的查看、手动编辑、导入导出和自定义表格结构。
- 完整的手动“追溯”工具：历史区间追溯、全部/单表追溯、分批执行、重构模式、表格优化、进度修正和结果确认。
- 选择一个或多个记忆表格生成总结。
- 在总结确认页重新生成结果，再决定是否保存。
- 总结成功后保留、隐藏或删除本次参与总结的源行。
- 将总结写入“记忆总结”表。
- 按配置的分隔符切片，默认使用 `===`。
- 每个切片独立生成 Embedding，并在后续聊天中按相似度检索注入。
- 未开启自动向量化时，使用“记忆总结（默认发送）”作为兜底上下文。

## 已移除功能

- AI 回复末尾的实时填表提示词与 `<Memory>` 自动执行流程。
- 日常聊天中按楼层自动触发的批量填表；手动“追溯”仍完整保留。
- 聊天历史总结、分批聊天总结和大总结。
- 总结优化/润色。
- 将总结同步到普通世界书的功能与界面。
- 上游仓库自动更新。

## 总结与向量化流程

1. 如需整理旧聊天，先用“追溯”将指定历史区间补填或重构到记忆表格；日常对话不会自动填表。
2. 在“总结”中选择要处理的记忆表格。
3. 选择总结成功后的源行处理方式：保留、隐藏或删除。
4. 总结模型输出被原样写入“记忆总结”表。
5. 向量模块只读取总结正文，不读取“剧情总结 N”等行标题或备注。
6. 正文按向量设置中的分隔符切片；默认 `===`，空片段会被过滤。
7. 每个切片独立向量化，并绑定到当前聊天的《剧情总结归档》。
8. 后续发送消息时，插件检索相关片段并注入最终请求正文。

## 向量数据存储说明

向量数据库仍通过 SillyTavern 的隐藏存储书 `Memory_Vector_Database` 持久化。这只是向量模块的内部存储层，不会作为记忆总结世界书绑定或注入，也不属于已经移除的“世界书总结同步”功能。保留该方式是为了避免浏览器 `localStorage` 容量不足导致向量丢失。

## 安装

在 SillyTavern 的“安装扩展”中使用以下仓库地址：

```text
https://github.com/LEASE-2473/ST-Memory-Context
```

也可以下载仓库 ZIP，将其解压到 SillyTavern 的第三方扩展目录，确保安装目录名与 SillyTavern 实际加载路径一致，然后刷新页面。
